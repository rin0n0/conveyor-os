# Conveyor OS

Переносимая операционная система для разработки и работы с ИИ-агентами. Она живёт на внешнем SSD (Intel SSD 545s 256 ГБ в USB-корпусе на мосте JMicron JMS578, `152d:0578`) и загружается на любом ПК с UEFI: дома, в колледже, на чужом ноутбуке. Ничего на компьютере-хозяине не меняется.

Образ системы собирается в GitHub Actions как контейнер (Fedora bootc 43), проходит автоматические проверки и публикуется в `ghcr.io/rin0n0/conveyor-os:latest`. Установщик разворачивает этот образ на SSD.

Документ состоит из трёх частей:

1. [Как это устроено](#часть-1-как-это-устроено) — архитектура, загрузка, сборка, все файлы репозитория.
2. [Как этим пользоваться](#часть-2-как-этим-пользоваться) — установка, первые шаги, ежедневная работа, модели.
3. [Что есть и чего нет](#часть-3-что-есть-и-чего-нет) — возможности, ограничения, ручные действия, история решённых проблем.

## Часть 1. Как это устроено

### Общая схема

```
GitHub (этот репозиторий)
   │  push в main или ночной запуск
   ▼
GitHub Actions: сборка образа → проверка образа → тест загрузки в VM → тест загрузки с USB
   │  только если все проверки прошли
   ▼
ghcr.io/rin0n0/conveyor-os:latest
   │  scripts/repair-and-install.sh с Live USB
   ▼
Внешний SSD: ESP + /boot + SHARED (exFAT) + LUKS2 (Btrfs)
   │
   ▼
Любой ПК с 64-битным UEFI
```

### Разметка SSD

Разметку создаёт `scripts/partition-intel-545s.sh`. Скрипт **стирает весь диск**.

| № | Размер | Файловая система | Назначение |
|---|---|---|---|
| 1 | 1 ГиБ | FAT32, метка `EFI` | Раздел EFI: загрузчики `\EFI\BOOT` и `\EFI\fedora` |
| 2 | 2 ГиБ | ext4, метка `BOOT` | Ядро `vmlinuz`, `initramfs.img`, копия `grub2/grub.cfg` |
| 3 | 50 ГиБ | exFAT, метка `SHARED` | Обмен файлами с Windows, Windows-помощник загрузки |
| 4 | остаток минус 25 ГиБ | LUKS2 → Btrfs | Сама система и данные |
| — | ~25 ГиБ | не размечено | Резерв для износа SSD (over-provisioning) |

LUKS2: `aes-xts-plain64`, ключ 512 бит, `argon2id`, сектор 4096 байт. Конец раздела 4 выравнивается по 4 КиБ (`sgdisk --align-end`), иначе `cryptsetup` отказывается создавать том с сектором 4096.

Подтома Btrfs внутри LUKS:

| Подтом | Точка монтирования | Особенности |
|---|---|---|
| `@root` | `/` | Сама ОС, перезаписывается при каждой установке |
| `@home` | `/var/home` | Домашние папки, установщик не трогает |
| `@models` | `/var/lib/models` | Веса моделей, без сжатия и без CoW (`chattr +C`) |
| `@containers` | `/var/lib/containers` | Хранилище Podman |
| `@var_cache` | `/var/cache` | Кэши |
| `@snapshots` | — | Зарезервирован под снимки, пока не используется |

`/etc/fstab` и `/etc/crypttab` генерирует установщик по UUID разделов, поэтому диск не зависит от того, как его назовёт ПК (`sdb`, `sdc` и т.д.). Раздел `SHARED` монтируется в `/mnt/shared` с `nofail`: если Windows оставила его «грязным», система всё равно загрузится.

### Цепочка загрузки

```
Прошивка UEFI
  └─ \EFI\BOOT\BOOTX64.EFI      (shim, подписан Microsoft UEFI CA)
       └─ grubx64.efi           (GRUB, подписан Fedora)
            └─ grub.cfg         (генерирует установщик)
                 └─ /vmlinuz + /initramfs.img   (раздел BOOT, ext4)
                      └─ initramfs: USB, клавиатура, LUKS → запрос пароля
                           └─ Btrfs @root → systemd → greetd
```

Как гарантируется загрузка на чужом ПК:

- **Путь по умолчанию.** Загрузчик лежит в `\EFI\BOOT\BOOTX64.EFI`. Любая UEFI-прошивка ищет его на съёмном диске сама, без записей в NVRAM.
- **Ничего не пишется в прошивку.** `fbx64.efi` (fallback из shim) сознательно не копируется: иначе shim при первой загрузке создавал бы записи в памяти каждого ПК.
- **Подписанные файлы берутся из образа.** Установщик копирует `shimx64.efi`, `grubx64.efi`, `mmx64.efi` из `/usr/lib/bootupd/updates/EFI/fedora` внутри образа, а не с Live-системы. После записи файлы сверяются побайтово, а при несовпадении установка завершается с ошибкой.
- **Один и тот же `grub.cfg` лежит в `\EFI\BOOT` и `\EFI\fedora`.** Fedora GRUB ищет конфиг рядом с собой и в `/EFI/fedora`, поэтому найдёт его при любом способе запуска.
- **Ядро всегда соответствует модулям.** Перед распаковкой образа старый `/usr/lib/modules` удаляется, а ядро и initramfs берутся из единственного каталога модулей образа. Замена атомарная: сначала `*.new`, потом `mv`.
- **Свой initramfs.** Он пересобирается при сборке образа (`dracut --no-hostonly`, конфиг `system/etc/dracut.conf.d/10-portable-usb.conf`). Внутри драйверы USB 1.1–3.x, `usb-storage`, `uas`, AHCI, NVMe, HID-клавиатура, `dm-crypt`, `systemd-cryptsetup`, Btrfs. Драйверы видеокарт исключены, они грузятся позже, уже по выбору из меню.
- **Метки SELinux.** `tar` теряет их при распаковке, и без меток `systemd` останавливается на старте. Установщик ставит метки через `chroot … setfiles` из самого образа, поэтому это работает с любой Live-системы. Если разметка не удалась, система переходит в `permissive` и делает `.autorelabel` при первой загрузке.

Меню GRUB (таймаут 5 секунд):

| Пункт | Когда выбирать | Что меняется |
|---|---|---|
| `Conveyor OS` | Обычный запуск | Драйвер NVIDIA, если Secure Boot выключен. Если включён, автоматически открытый драйвер (по переменной GRUB `$lockdown`) |
| `Conveyor OS (open NVIDIA driver: older cards)` | NVIDIA старше Turing (GTX 10xx и раньше) или проблемы с фирменным драйвером | Фирменный драйвер NVIDIA запрещён, работает `nouveau` |
| `Conveyor OS (safe mode: slow USB, basic graphics)` | Диск зависает на USB, чёрный экран | USB в режиме BOT вместо UAS (`usb-storage.quirks=152d:0578:u`), `nomodeset` |

Общие параметры ядра: `root=UUID=…`, `rootflags=subvol=@root`, `rd.luks.name=<UUID>=conveyor_crypt`, `rootwait`, `usbcore.autosuspend=-1`. Последний отключает засыпание USB, чтобы корневой диск не отваливался.

### Определение железа при загрузке

`boot-gpu-detect.service` → `/usr/local/libexec/boot-gpu-detect.sh`. Запускается после загрузки драйверов (`udevadm settle`), но до входа в систему и до `llama-swap`.

1. Ждёт появления DRM-устройства (до 5 секунд, кроме `nomodeset`).
2. Разбирает вывод `vulkaninfo`: тип устройства (дискретное или встроенное), версию Vulkan (нужна 1.2+) и самую большую область `DEVICE_LOCAL` памяти у дискретной карты.
3. Записывает `/run/gpu-profile.env`: `GPU_BACKEND`, `VRAM_GIB`, `RAM_GIB`, `WAYLAND_RENDER_MODE`, `LLAMA_PROFILE`.
4. Делает ссылку `/run/llama-swap-active.yaml` на профиль моделей: при 7+ ГБ видеопамяти `config-8gb-vram-32gb-ram.yaml`, иначе `config-cpu-only.yaml`. Встроенная графика считается как 0 ГБ, потому что делит обычную память.

При любой ошибке скрипт оставляет рабочий профиль CPU и не мешает загрузке.

### Графическая среда

Вход через `greetd` + `tuigreet` (текстовый экран входа, запоминает пользователя и сессию). Сессии описаны в `system/usr/share/wayland-sessions/` и запускаются через `session-wrapper.sh`:

| Сессия | Что это | Для чего |
|---|---|---|
| DriftWM | Бесконечный 2D-холст, окна как «острова» | Основная, собирается из исходников `malbiruk/driftwm` |
| Niri | Горизонтальные ленты окон, обзор `Super+O` | Клавиатурный тайлинг |
| Sway | Классический тайлинг wlroots | Запасной вариант для слабого железа |

`session-wrapper.sh` перед запуском оболочки:

- загружает `/run/gpu-profile.env` и включает программный рендер, если GPU не годится;
- задаёт Wayland-переменные, терминал `foot` и редактор `micro`;
- запускает `conveyor-user-migrate.sh`, который обновляет конфиги в домашней папке;
- в фоне запускает `conveyor-user-setup.sh`, который ставит Antigravity CLI и подключает Flathub;
- для Sway на драйвере NVIDIA добавляет `--unsupported-gpu`.

Панель `waybar` показывает проект, число активных агентов, очередь `pueue`, VRAM, память, CPU, звук, время. Уведомления через `swaync`, лаунчер `fuzzel`, мониторы `kanshi` (только в Niri), история буфера `cliphist`.

### Видеокарта NVIDIA

- Открытые модули ядра NVIDIA собираются при сборке образа отдельной стадией `nvidia-builder`: `akmod-nvidia` из репозитория negativo17 под точное ядро базового образа. Если `kernel-devel` уже пропал с зеркал, он берётся из Koji.
- В итоговый образ ставятся `kmod-nvidia`, `nvidia-driver` и `nvidia-driver-cuda` (Vulkan, CUDA-библиотеки, `nvidia-smi`).
- Запрет `nouveau` из пакетов NVIDIA удаляется. Выбор между драйверами делается параметрами ядра в меню GRUB, чтобы на ПК со старой NVIDIA оставался рабочий вариант.
- Модули не подписаны: при включённом Secure Boot они не загрузятся. Тогда автоматически используется `nouveau` или простой кадровый буфер.
- `system/etc/nvidia/nvidia-application-profiles-rc.d/…json` ограничивает пул видеопамяти у оболочек Niri, Sway и DriftWM. Без этого они держат лишние сотни мегабайт VRAM, нужные моделям.
- `system/usr/lib/bootc/kargs.d/10-conveyor-nvidia.toml` содержит те же параметры ядра для будущей установки через bootc.

### Локальные модели

```
Клиенты (aider, opencode, редакторы, curl)
   │  OpenAI-совместимый API
   ▼
llama-swap  127.0.0.1:8080   (веб-интерфейс: /ui)
   │  запускает нужный llama-server по имени модели
   ▼
llama-server (llama.cpp, Vulkan + все варианты CPU)
   │
   ▼
/var/lib/models/active-<роль>.gguf  → ссылка на реальный файл
```

- `llama.cpp` собирается с `GGML_BACKEND_DL` и `GGML_CPU_ALL_VARIANTS`: одна сборка сама выбирает инструкции процессора (SSE4.2 … AVX-512) и Vulkan во время работы. Бэкенды `libggml-cpu-*.so` и `libggml-vulkan.so` лежат рядом с `llama-server` в `/usr/local/bin`.
- `llama-swap.service` — системная служба (от root), слушает только `127.0.0.1:8080`, ограничение памяти `MemoryHigh=24G`.
- Роли одинаковы в обоих профилях, поэтому клиенты не нужно перенастраивать при смене ПК:

| Роль | Назначение | Псевдонимы |
|---|---|---|
| `coder` | Основная модель для кода | `default`, `qwen-coder`, `gpt-4o`, `claude-3-5-sonnet` |
| `fast` | Быстрые ответы, чат | `chat`, `fast-triage`, `local-fast`, `gpt-4o-mini` |
| `think` | Рассуждения, математика | `reasoning`, `local-deep`, `o1`, `deepseek-r1` |
| `embed` | Эмбеддинги для поиска (CPU) | `rag-embed`, `text-embedding-3-small` |

- `coder`, `fast` и `think` в одной группе, поэтому одновременно работает только одна из них. `embed` в отдельной постоянной группе и не выгружается при переключении.
- **Профиль GPU** (`config-8gb-vram-32gb-ram.yaml`): число слоёв и контекст не заданы, `llama-server --fit on` сам подбирает их под свободную VRAM, оставляя 512 МиБ рабочему столу (`--fit-target 512`). Что не влезло, уходит в RAM. Минимальный контекст: 16384 для `coder` и `think`, 8192 для `fast`. Кэш K/V квантуется в `q8_0`, используется Flash Attention, `--parallel 1` (один пользователь, весь контекст ему).
- **Профиль CPU** (`config-cpu-only.yaml`): всё на процессоре, контекст 8192.
- Время простоя до выгрузки: `coder` 60 минут, `think` 30, `fast` 15 (в профиле GPU). В профиле CPU общий таймаут 10 минут.

Также в образе есть `whisper-cli` (распознавание речи на CPU) и скрипт `conveyor-comfyui.sh` (генерация изображений, ставится в домашнюю папку при первом запуске).

### Сборка образа

`Containerfile` — многостадийная сборка, все внешние версии закреплены в `ARG`:

| Стадия | Что делает | Закреплённые версии |
|---|---|---|
| `llama-builder` | Собирает `llama-server` и `whisper-cli` | `llama.cpp v1.0.0`, `whisper.cpp v1.9.5` |
| `rust-builder` | Собирает DriftWM под `x86-64-v2` | `driftwm v0.21.0` |
| `tools-downloader` | Скачивает готовые программы | `llama-swap 273`, `jj v0.47.1`, `mise v2026.11.9`, `ast-grep 0.51.3`, `pueue v4.0.4`, `zellij v0.46.0`, `yazi v26.9.1`, `cliphist v0.7.0`, `opencode v1.19.6` (baseline, работает без AVX2) |
| `nvidia-builder` | Собирает модули NVIDIA под ядро образа | последний драйвер negativo17 на дату сборки |
| финальная | `fedora-bootc:43` + пакеты + всё выше + конфиги | `aider-chat 0.86.2` (на Python 3.12) |

Финальная стадия по порядку:

1. Ставит пакеты Fedora. Список закрыт: если пакет не найден, сборка падает.
2. Ставит драйвер NVIDIA.
3. Ставит `aider` через `uv tool` на Python 3.12, потому что `aider` не поддерживает Python 3.13+.
4. Копирует собранные программы и `system/` поверх корня образа.
5. Включает службы, ставит графический режим по умолчанию.
6. Пересобирает initramfs.
7. Запускает `conveyor-check-image.sh`.
8. Запускает `bootc container lint`.

`conveyor-check-image.sh` проверяет, что:

- все обещанные команды существуют, а `llama-server`, `whisper-cli`, `aider`, `opencode` и `llama-swap` действительно запускаются;
- бэкенды `llama.cpp` лежат рядом с исполняемым файлом;
- есть модули `nvidia`, `nvidia_drm`, `nvidia_modeset`, `nvidia_uvm` и `nouveau`, `nouveau` не запрещён, есть Vulkan-драйвер NVIDIA;
- оба профиля `llama-swap` стартуют и отдают роли `coder`, `fast`, `think`, `embed`;
- конфиги Niri, Waybar и DriftWM корректны, все скрипты без синтаксических ошибок;
- в образе есть подписанные EFI-файлы и ядро;
- в initramfs есть USB, `dm-crypt`, Btrfs и `systemd-cryptsetup`, но нет драйверов GPU;
- на месте Windows-помощники загрузки.

### CI: `.github/workflows/build-bootc.yml`

Запуск: каждый push в `main` (кроме изменений только `README.md` и `docs/`), каждую ночь в 01:30 UTC и вручную.

| Задача | Что делает |
|---|---|
| `build` | Собирает образ и публикует его как `sha-<коммит>`. Передаёт дату в `REFRESH_DATE`, поэтому раз в сутки пакеты Fedora и драйвер NVIDIA обновляются, а остальные стадии берутся из кэша. При ошибке повторяет сборку с подробным выводом и выносит ошибки в аннотации запуска |
| `vm-test` | `bootc install to-disk` на виртуальный диск, загрузка в QEMU с UEFI. Ждёт графического режима и проверяет, что `greetd`, `llama-swap` и `boot-gpu-detect` не упали |
| `usb-boot-test` | Повторяет реальный путь: `partition-intel-545s.sh` и `repair-and-install.sh` на виртуальный диск 120 ГБ. Затем загрузка как с USB на чистой прошивке без записей, отдельно без Secure Boot и с Secure Boot (ключи Microsoft). Скрипт сам вводит пароль LUKS (`ci-usb-boot-qemu.py`) и проверяет, что Secure Boot действительно был включён |
| `promote` | Только если всё выше прошло, ставит тег `latest` на проверенный образ |

Ручной запуск с флагом `skip_vm_test` публикует `latest` без тестов загрузки. Это аварийный вариант.

Если сборка упала, причину видно в аннотациях запуска на GitHub, даже без входа в аккаунт. Журналы последовательной консоли тестов сохраняются как артефакты `vm-serial-log` и `usb-serial-logs`.

## Часть 2. Как этим пользоваться

### Установка и обновление

Нужна Live-система Linux (Fedora Workstation Live подходит лучше всего) с `podman`, `cryptsetup`, `openssl`, `sgdisk` и поддержкой Btrfs и exFAT в ядре. Установщику нужно около 10–15 ГБ свободного места на целевом диске для временного хранения образа. Скачанное он держит на самом SSD, а не в оперативной памяти Live-системы.

**Новый диск** (все данные на нём будут удалены):

```bash
git clone https://github.com/rin0n0/conveyor-os.git
cd conveyor-os
lsblk -o NAME,SIZE,MODEL,TRAN
sudo bash scripts/partition-intel-545s.sh /dev/sdX
sudo bash scripts/repair-and-install.sh /dev/sdX
```

Скрипт разметки попросит ввести `YES`, затем `cryptsetup` ещё раз попросит `YES`, дважды новый пароль LUKS и тот же пароль для открытия тома. Установщик спросит пароль LUKS, только если том уже закрыт, и попросит задать пароль пользователя `conveyor`. Если в Live-системе нет `sgdisk`, поставьте его: `sudo dnf install gdisk`.

**Обновление или восстановление** (диск уже размечен):

```bash
sudo bash scripts/repair-and-install.sh /dev/sdX
```

Необязательный второй аргумент — другой образ, например `ghcr.io/rin0n0/conveyor-os:sha-1b9f9f8`. Так можно откатиться на конкретную сборку.

Что делает установщик по шагам:

1. Проверяет наличие `openssl` и разделов. Включает zram на Live-системе, чтобы она не упала от нехватки памяти.
2. Открывает LUKS. Создаёт недостающие подтома.
3. Монтирует всё в `/mnt/target`. Хранилище Podman переносит на целевой SSD.
4. Запоминает хеш пароля пользователя, если это не старый стандартный `conveyor`.
5. Скачивает образ и распаковывает его в `@root`, предварительно удалив старые модули ядра.
6. Создаёт пользователя `conveyor`, ставит пароль (сохранённый или новый), блокирует вход под `root`, включает `sudo` с паролем.
7. Пишет `fstab` и `crypttab`.
8. Ставит ядро, initramfs, подписанные загрузчики и `grub.cfg`. Копирует Windows-помощник в `SHARED\ConveyorOS`.
9. Ставит метки SELinux.
10. Сверяет загрузчики и ядро с образом.

**Что сохраняется при обновлении:** всё в `@home`, `@models`, `@containers`, `@var_cache`, сохранённые сети Wi-Fi и проводные профили (`/etc/NetworkManager/system-connections`, их нет в образе), пароль пользователя.

**Что перезаписывается:** все файлы ОС из образа, включая `/etc/passwd`, `/etc/shadow`, `fstab`, `crypttab`, загрузчики. Программы, поставленные через `sudo dnf install` прямо в систему, после обновления могут сломаться, поэтому так делать не стоит. Как ставить программы правильно, описано ниже.

### Как загрузиться на конкретном ПК

Подключите SSD **до включения** компьютера: многие прошивки с быстрой загрузкой не опрашивают USB, если диск подключили позже.

**Через меню прошивки.** Клавиша меню загрузки (обычно `F12`, `F11`, `F8`, `Esc`) → USB-диск. Он называется по данным прошивки, например `UEFI: JMicron` или `EFI USB Device`.

**Из Windows, разово.** «Параметры» → «Система» → «Восстановление» → «Особые варианты загрузки» → «Перезагрузить сейчас» → «Использовать устройство» → диск.

**Из Windows, с пунктом «Conveyor OS».** На диске `SHARED` откройте `ConveyorOS\Boot-Conveyor-OS.cmd` и подтвердите запрос администратора. Скрипт `Conveyor-Boot.ps1`:

1. находит раздел EFI на том же физическом диске, с которого запущен;
2. временно подключает его и проверяет `\EFI\BOOT\BOOTX64.EFI`;
3. создаёт запись `Conveyor OS` в списке загрузки ПК через `bcdedit` (Windows Boot Manager остаётся первым);
4. предлагает сразу перезагрузиться в Conveyor OS один раз (`bootsequence`).

После этого пункт `Conveyor OS` виден и в «Использовать устройство». Запись привязана к разделу этого SSD. Удалить её: открыть PowerShell от имени администратора и выполнить `Conveyor-Boot.ps1 -Remove`. Если на диске Windows включён BitLocker, скрипт предупредит: держите ключ восстановления под рукой.

**Secure Boot.**

- Выключен: работает всё, включая драйвер NVIDIA.
- Включён: система загрузится, но с открытым драйвером видеокарты.
- Если прошивка разрешает только загрузчики Microsoft (бывает на ноутбуках Secured-core), включите в BIOS «Allow Microsoft 3rd Party UEFI CA» или отключите Secure Boot.

**Дома (RTX 3060 Ti):** Secure Boot нужно выключить, иначе драйвер NVIDIA не загрузится. У i3-12100F нет встроенной графики, поэтому без драйвера NVIDIA не будет ускорения моделей.

### Первые шаги после запуска

1. **Пароль LUKS.** Вводится в текстовом режиме сразу после меню GRUB.
2. **Вход.** На экране `tuigreet` выберите сессию (`F3`) и войдите как `conveyor`. Сессия и пользователь запоминаются.
3. **Сеть.** Проводная обычно подключается сама.
   - Wi-Fi через терминал: `nmtui`. Графически: `Super+N` в DriftWM, либо `nm-connection-editor` через лаунчер.
   - Быстрое переключение профилей: `Super+Shift+N` в DriftWM.
4. **Дождитесь уведомления «Antigravity CLI установлен».** Установка начинается примерно через 15 секунд после входа, когда появится интернет. Если не вышло, система повторит при следующем входе. Журнал: `~/.local/state/conveyor/user-setup.log`.
5. **Войдите в Antigravity CLI.** Откройте терминал (`Super+Enter`), введите `agy` и пройдите вход в аккаунт Google.
6. **Проверьте железо:**

   ```bash
   cat /run/gpu-profile.env
   nvidia-smi
   systemctl status llama-swap
   ```

   На домашнем ПК ожидается `GPU_BACKEND=vulkan`, `VRAM_GIB=7` или `8` и профиль `config-8gb-vram-32gb-ram.yaml`.
7. **Скачайте и назначьте модели** (подробно ниже).
8. **Поставьте нужные программы** через Flatpak или Distrobox (подробно ниже).
9. **Создайте проект:** `Super+P` → «➕ Новый проект».

### Работа с моделями

**1. Скачайте файл модели в формате GGUF**, например с Hugging Face через Firefox. Удобно класть файлы:

- в `~/Downloads`;
- на `SHARED` (`/mnt/shared/models`) — тогда тот же файл можно скачать из Windows;
- в `/var/lib/models` — зашифрованный подтом.

Ориентиры для RTX 3060 Ti (8 ГБ VRAM) и 32 ГБ RAM:

- модели до 7–9 млрд параметров в `Q4_K_M` (примерно 4,5–6 ГБ) целиком помещаются в видеопамять и работают быстрее всего;
- модели на 12–14 млрд частично уходят в RAM, работают медленнее;
- MoE-модели с маленьким числом активных параметров (например, 30B-A3B) удобно держать в RAM: `--fit` сам разложит слои.

Для `embed` нужна отдельная модель эмбеддингов в GGUF.

**2. Назначьте файл роли:**

```bash
conveyor-model
```

Без аргументов команда работает интерактивно: ищет `.gguf`, `.safetensors` и `.ckpt` в `/mnt/shared/models`, `/mnt/shared`, `~/Downloads`, `/var/lib/models`, затем спрашивает роль и способ подключения:

- **ссылка:** файл остаётся на месте;
- **копия:** файл копируется в `/var/lib/models`.

Без интерактива:

```bash
conveyor-model install ~/Downloads/model.gguf coder        # ссылка
conveyor-model install ~/Downloads/model.gguf coder copy   # копия в /var/lib/models
conveyor-model list                                        # текущие назначения
```

После назначения команда выгружает запущенные модели, поэтому следующий запрос уже использует новый файл. Роли `comfy-checkpoint` и `comfy-lora` подключают файлы к ComfyUI.

Если файл лежит на `SHARED`, роль работает, только пока раздел смонтирован. Для постоянной работы лучше копия.

**3. Проверьте:**

```bash
curl http://127.0.0.1:8080/v1/models
curl http://127.0.0.1:8080/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"model":"coder","messages":[{"role":"user","content":"Привет"}]}'
```

Первый запрос медленный: модель загружается в память. Журналы, загруженные модели и ручная выгрузка доступны в Firefox: <http://127.0.0.1:8080/ui>. Журнал службы: `journalctl -u llama-swap -f`.

**4. Подключите клиентов.** Адрес API для любой программы с поддержкой OpenAI: `http://127.0.0.1:8080/v1`. Ключ не проверяется, подойдёт любая строка.

```bash

```

### Когда что-то пошло не так

| Симптом | Что делать |
|---|---|
| Диска нет в меню загрузки | Подключить до включения ПК, отключить Fast Boot, проверить что USB-загрузка разрешена и включён режим UEFI (не Legacy/CSM) |
| `Security Violation` / `Access Denied` при старте | Разрешить сторонние сертификаты UEFI или отключить Secure Boot |
| Зависание после выбора пункта, ошибки USB | Пункт `safe mode` |
| Чёрный экран на NVIDIA | Пункт `open NVIDIA driver`, затем `safe mode` |
| Нет ускорения моделей | `cat /run/gpu-profile.env`, `nvidia-smi`. Проверить, что Secure Boot выключен |
| Модель не отвечает | `journalctl -u llama-swap -f`, `conveyor-model list`: есть ли ссылка и существует ли файл |
| Нет `agy` | `~/.local/state/conveyor/user-setup.log`, перезайти в сессию |
| Сломались настройки оболочки после обновления | Старые файлы лежат в `~/.config/conveyor/backup-v*` |
| Система не грузится совсем | Загрузиться с Live USB и запустить `repair-and-install.sh` ещё раз |

## Часть 3. Что есть и чего нет

### Работает и проверено в CI

- Сборка образа целиком, с проверкой каждой обещанной программы.
- Загрузка в виртуальной машине через bootc до экрана входа.
- Разметка, установка и загрузка с USB на чистой UEFI с Secure Boot и без него, включая разблокировку LUKS.
- Запуск обоих профилей моделей и всех ролей.

### Есть, но не проверено на реальном железе

- Работа драйвера NVIDIA на RTX 3060 Ti и выбор профиля GPU.
- Автоматический переход на открытый драйвер при включённом Secure Boot (переменная GRUB `$lockdown`).
- Windows-помощник `Boot-Conveyor-OS.cmd`: проверен только синтаксис, потому что запуск меняет настройки прошивки ПК.
- Автоподбор сети колледжа, диктовка, ComfyUI.

### Чего пока нет

### Что нужно делать вручную

- Отключить Secure Boot на домашнем ПК.
- Войти в Antigravity CLI (`agy`).
- Скачать модели и назначить роли через `conveyor-model`.
- Создать профили Wi-Fi и сетей колледжа. Для автоподбора нужны профили со статическим IPv4 и шлюзом: скрипт проверяет шлюзы по очереди и включает тот профиль, чей шлюз ответил.
- Ставить программы через Flatpak, Distrobox, `mise`, `uv`.
- Обновлять систему: запускать `repair-and-install.sh` с Live USB.
- На чужом ПК, если нужно: один раз запустить Windows-помощник.

### Замечания о настройках

- `~/.config/mise/config.toml` задаёт `ANTHROPIC_BASE_URL` и `OPENAI_BASE_URL` на локальный `llama-swap`. Они действуют, только если `mise` активирован в оболочке (`mise activate`), и тогда направят Claude Code и другие клиенты на локальную модель. Если нужен облачный доступ, уберите эти строки.
- `sudo` спрашивает пароль. Вход под `root` закрыт.
- Внутренние диски ПК-хозяина не монтируются автоматически, но вручную доступны (`sudo mount`). Будьте осторожны на чужих компьютерах.

### История: какие проблемы и как решали

**Загрузка и установка**

| Проблема | Причина | Решение |
|---|---|---|
| После установки не работал `bootc upgrade` | Установщик распаковывал образ как обычный архив и удалял ostree. `install-to-usb.sh` вызывал `bootc` с несуществующими флагами | Сейчас один установщик с распаковкой. Переход на bootc — этап 1 |
| Загрузчики могли быть с Live-системы | Скрипт не находил EFI-файлы образа и брал файлы хоста или вызывал `grub-install` хоста | Файлы берутся из `/usr/lib/bootupd/updates` образа, с проверкой |
| Новые модули при старом ядре | При повторной установке находился старый `/boot/vmlinuz` | Старые модули удаляются, ядро берётся из единственного каталога образа |
| Настройки initramfs не применялись | Конфиг dracut лежал в образе, но initramfs не пересобирался | Пересборка при сборке образа и проверка состава |
| `systemd` останавливался на старте | Метки SELinux терялись при распаковке | Разметка через `setfiles` из образа |
| `cryptsetup` отказывался создавать том | Размер раздела не делился на 4 КиБ | `sgdisk --align-end` |
| Разделы NVMe и loop не находились | Имена вида `nvme0n1p1`, а не `sdb1` | Учитывается суффикс `p` |
| Live-система падала от нехватки памяти, конфликты SELinux из-за жёстких ссылок, гонка имён LUKS | Ранние версии установщика | Хранилище Podman на целевом диске, удаление `/sysroot/ostree`, `rd.luks.name` совпадает с `crypttab` |

**Сборка**

| Проблема | Причина | Решение |
|---|---|---|
| Ошибки установки скрывались | `--skip-unavailable` и `\|\| true` | Сборка падает на любой ошибке, плюс проверка образа |
| Сборки были невоспроизводимы | Всё скачивалось как `latest` | Версии закреплены, ночная сборка обновляет только пакеты Fedora |
| `aider` не ставился | Fedora 43 использует Python 3.14, `aider` поддерживает до 3.12 | `uv tool` на Python 3.12 |
| `opencode` не ставился | npm-пакет не прошёл проверку запуска своей программы и попытался поставить musl-версию | Готовый архив релиза (baseline) |
| `llama.cpp` не собирался | Скачанный веб-интерфейс не прошёл проверку версии | Встроенный интерфейс отключён, есть интерфейс `llama-swap` |
| `whisper-cli` не запускался | В образ попадал файл программы без её библиотеки | Статическая сборка |
| Логи CI не видны без входа | GitHub не отдаёт журналы анонимно | Ошибки выносятся в аннотации |

**Рабочая среда**

| Проблема | Причина | Решение |
|---|---|---|
| `Super+Enter` не открывал терминал в Niri и Sway | Вызывался `footclient` без сервера `foot` | Прямой вызов `foot` |
| В DriftWM не было русской раскладки, в Niri и Sway переключение конфликтовало с `Super+Space` | Не настроено / одна комбинация на два действия | Раскладка `us,ru` и `Alt+Shift` везде |
| Не работала история буфера | `cliphist` нет в Fedora | Скачивается при сборке, автозапуск во всех оболочках |
| Переключатель проектов падал | Писал в `/run` без прав, вызывал `footclient` | Файл в `$XDG_RUNTIME_DIR`, `foot` |
| Исправления конфигов не доходили до пользователя | `/etc/skel` применяется только к новым пользователям | `conveyor-user-migrate.sh` с резервной копией |
| Пароль `conveyor` у всех и `sudo` без пароля | Значения по умолчанию в установщике | Пароль задаётся при установке, `sudo` с паролем, `root` закрыт |

**Модели и видеокарта**

| Проблема | Причина | Решение |
|---|---|---|
| Роли моделей не работали на слабых ПК | Профиль CPU ссылался на конкретные файлы, а не на роли | Одинаковые роли в обоих профилях |
| Группы моделей описаны в устаревшем формате | Изменился формат конфига `llama-swap` | `routing.router.settings.groups` |
| Мощный профиль мог не включиться | Определение запускалось до загрузки драйверов GPU | Запуск после udev, определение через Vulkan |

| Модели не умещались в 8 ГБ | `-ngl 99` и фиксированный контекст 32K | `--fit` с запасом 512 МиБ |
| Нельзя писать в `/var/lib/models` без `sudo` | Права root | `tmpfiles` даёт запись группе `wheel` |
